# testScenario1.txt
# -------------------------------------------------------------------------
# End-to-end scenario for the Supermarket Checkout System CLUI.
# Written to run cleanly against the current implementation:
#   - passwords are integers (parsed with Integer.parseInt)
#   - registration addresses are single tokens (registerCustomer needs 5 args)
#   - delivery addresses are taken from the pre-loaded address book
#   - card numbers fit in int; the registered test card is 1234 / PIN 0
#
# What this scenario tests:
#   1. Manager login + registration of a cashier and a customer.
#   2. Category-level pricing policy (R6: -10% on fruit-and-vegetables).
#   3. Customer subscription to the 'prime' plan (R5).
#   4. Home delivery request to a known address (R7).
#   5. Mixed cart across all three mandatory categories (R2b) with
#      quantity-based pricing (R3), category discount (R6), prime plan (R5),
#      and plan-based delivery fee reduction (R8/R8b).
#   6. Forced INSUFFICIENT_FUNDS, then a real successful payment (R4).
#   7. Low-stock notification via the Observer pattern (R9).
#   8. Manager inspecting inventory and revenue.
#
# Lines starting with '#' are comments and are ignored by runTest.
# NOTE: the default configuration is already loaded at startup, so there is
# no need to call 'setup' again here.
# =========================================================================


# ---- 1. Manager logs in and registers staff/customer ----
login ceo 123456789
registerCashier Bob Dupont bob 3333
registerCustomer Alice Martin alice paris 4444

# ---- 2. Category-level discount (R6): 10% off fruit-and-vegetables ----
setCategoryDiscount fruit-and-vegetables 10
logout


# ---- 3. Default customer subscribes to 'prime' and requests delivery ----
# (the default customer 'customer' has card 1234, PIN 0, password 2222)
login customer 2222
subscribeToPlan prime
requestDelivery rue de rivoli, 75001 paris
logout


# ---- 4. Cashier opens a checkout for the default customer ----
login bob 3333
startCheckout customer
# apple is fruit-and-veg: bulk price (10+ -> 20% off unit) AND category -10%
scanItem apple 10
# yogurt is dairy: bulk price (4+ -> 10% off unit), no category discount
scanItem yogurt 4
# chicken is meat: bulk price (4+ -> 10% off unit), no category discount
scanItem chicken 6
# Bill should combine: quantity pricing + category discount + prime (subtotal
# >= 50 so 20% off) + delivery (10kg within 30km = 15 EUR, prime pays 50%).
computeBill

# ---- 5. First payment is forced to fail, then a real retry succeeds ----
simulatePayment INSUFFICIENT_FUNDS
pay 1234 0
# No override is armed now, so this goes through the real bank flow and
# succeeds (card 1234 exists, PIN 0 matches, balance 500 covers the bill).
pay 1234 0
logout


# ---- 6. Trigger the R9 low-stock Observer notification on chicken ----
# Manager restocks chicken to 6 (threshold is 5), then a sale of 5 leaves 1
# in stock, which fires the Supplier's low-stock alert.
login ceo 123456789
restock chicken 6
logout

login bob 3333
startCheckout alice
scanItem chicken 5
computeBill
# Force success so this step doesn't depend on a specific card number.
simulatePayment SUCCESS
pay 0 0
logout


# ---- 7. Manager inspects the resulting state ----
login ceo 123456789
showInventory
showRevenue
logout
